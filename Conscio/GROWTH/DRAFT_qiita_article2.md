# 仕組み: 三層ループ

`sleep`コマンドを3本、役割を分けて発火させるだけの構造ですが、1日運用で壊れませんでした。

| レーン | 間隔 | 役割 |
|--------|------|------|
| main | 30分 | 進化ティック本体（バックログ先頭を実装→build→push→記録） |
| backup | 47分 | mainが死んだ時だけ検知して復旧。生きていれば**無言で退場**（増殖しない） |
| emergency | 3時間 | 最終保険。発火してもheartbeatが新鮮なら何もしない |

ポイントは3つ:

1. **再アームを必ず先にやる** — 作業で例外が出ても次のタイマーは生きている
2. **heartbeat（心拍）をファイルに残す** — backupが「32分以上更新がなければ復旧」と判定する。これで乱発火がなく
3. **復旧手順書をリポジトリにコミット** — セッションが死んでも次の再開者が読める（RECOVERY_PROTOCOL.md）

実装は素朴です。だからこそ、障害ゼロで1日回りました。

# 本丸: ループが見つけた「見せかけ」とその修正

放置していて一番価値があったのは、**速さではなく誠実さのリファクタ**でした。

1. **偽スコアの撤去**: レポートに「集中達成スコア 88/100・先週比+12%」という固定値が残っていました → 「目標60分/日の達成率」の実データ計算に置換
2. **デモ提案の全面撤去**: 本番UIに存在しない文書やexample.comへのリンクが入っていた → 提案欄は実在するものだけに（戻る提案＋実キーワード検索のみ）
3. **macOS仕様の正直化**: 「◯件の通知を抑制しました」という文言が、macOSの仕様上（他アプリの通知はOS管理で取得不可）**根拠を持たない**と判明 → 通知の代わりに「◯◯での集中セッション: ◯分」の実データ報告に刷新し、OSの限界は仕様として透明に表記

ここは教訓が大きくて、**「自動化は速い嘘を大量生産できる」**ということです。
ループに первоначoffsから「偽値禁止」「誇張禁止」の規則を書いておいたのが効きました（1人でもAIでも守れるルールとして共有）。
